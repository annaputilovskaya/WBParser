# Wildberries Parser

Парсер данных с сайта Wildberries для сбора полной информации о товарах по заданным поисковым запросам. Проект реализует продвинутую стратегию обхода ограничений API Wildberries и предоставляет готовые Excel-отчёты с фильтрацией по бизнес-критериям.

## Ключевые возможности

- **Полный цикл сбора данных** – от поиска до детальной информации о каждом товаре
- **Обход лимитов Wildberries** – интеллектуальное деление ценовых диапазонов для сбора более 1200 товаров
- **Богатый набор полей** – 15+ характеристик включая описание, изображения, размеры, остатки, рейтинг и страну производства
- **Автоматическая фильтрация** – генерация отдельного отчёта с товарами, соответствующими бизнес-требованиям
- **Многопоточная архитектура** – высокая производительность с контролируемой нагрузкой на сервер
- **Готовые Excel-отчёты** – структурированные файлы с форматированием и удобной организацией данных
- **Контейнеризация** – готовые Dockerfile и docker-compose для изолированного запуска
- **Профессиональная конфигурация** – настройки через переменные окружения с валидацией (pydantic-settings)
- **Продвинутое логирование** – ротация логов, JSON-формат, разделение потоков
- **Тестовое покрытие** – модульные и интеграционные тесты (pytest, покрытие — реальный бейдж в начале README)

## Собираемые данные

Для каждого товара парсер извлекает:

| Поле | Описание |
|------|----------|
| **Ссылка на товар** | Прямая ссылка на карточку товара |
| **Артикул** | Уникальный идентификатор товара (nmId) |
| **Название** | Полное наименование товара |
| **Цена** | Текущая цена в рублях |
| **Описание** | Детальное описание товара |
| **Изображения** | Ссылки на все доступные изображения (через запятую) |
| **Характеристики** | Все технические характеристики с сохранением структуры |
| **Продавец** | Название продавца (селлера) |
| **Ссылка на продавца** | Профиль продавца на Wildberries |
| **Размеры** | Доступные размеры товара |
| **Остатки** | Количество товара на складе |
| **Рейтинг** | Средний рейтинг товара (0-5) |
| **Отзывы** | Количество отзывов |

## Техническая реализация

### Стратегия обхода ограничений
Wildberries ограничивает выдачу 1200 товаров на один поисковый запрос. Для обхода этого ограничения парсер использует:

1. **Ценовые диапазоны** – начальное разбиение на широкие ценовые коридоры
2. **Рекурсивное деление** – если в диапазоне больше 1200 товаров, он делится пополам
3. **Пагинация** – последовательный обход всех страниц в каждом допустимом диапазоне

### Многопоточная обработка
Для ускорения сбора детальной информации используется `ThreadPoolExecutor`:
- Параллельная обработка до 30 товаров одновременно
- Контролируемые задержки между запросами
- Повторные попытки при ошибках сети

### Управление токенами
Автоматическое получение и обновление токенов аутентификации.

### Улучшенная конфигурация
- Все настройки вынесены в переменные окружения с префиксом `WB_`
- Используется библиотека `pydantic-settings` для валидации типов и значений
- Поддержка `.env` файла для локальной разработки
- Валидация критических параметров (таймауты, ретраи, размеры логов)

### Продвинутое логирование
- Ротация логов с ограничением размера файла (10 МБ) и количеством копий (5)
- Разделение потоков: DEBUG/INFO в `app.log`, ERROR/CRITICAL в `errors.log`
- Поддержка JSON-формата для интеграции с Docker и ELK-стеком
- Контекстное логирование с артикулами товаров и номерами попыток

## Установка и запуск с использованием Poetry (рекомендуется)

### Клонирование и установка
```bash
git clone https://github.com/annaputilovskaya/WBParser.git wb-parser
cd wb-parser
poetry install
```

### Настройка окружения
Скопируйте шаблон переменных окружения и при необходимости отредактируйте:
```bash
cp .env.example .env
```

### Запуск парсера
```bash
poetry run python src/main.py
```

## Запуск через Docker

### Быстрый старт (один запуск)
```bash
# Подготовка папок для данных, логов и кэша
mkdir -p data/output data/logs data/cache

# Сборка образа и одноразовый запуск парсинга
docker compose --profile batch run --build wbparser
```

### Полезные команды
- **Просмотр логов:** `docker compose logs -f`
- **Остановка:** `docker compose down`

### Ручная сборка Docker-образа
```bash
docker build -t wbparser:latest .
docker run --env-file .env \
  -v ./data/output:/app/data/output \
  -v ./data/logs:/app/data/logs \
  wbparser:latest
```

### Конфигурация Docker Compose
- **Персистентность данных** — отчёты, логи и кэш сохраняются на хост (`./data/output`, `./data/logs`, `./data/cache`).
- **Одноразовая джоба** — `restart: "no"`, профиль `batch` защищает от случайного `docker compose up`.
- **Гибкость** — полная поддержка настройки через `.env` без необходимости пересборки образа.

## Настройка параметров

### Использование .env файла
Все параметры парсера настраиваются через переменные окружения. Скопируйте `.env.example` в `.env` и отредактируйте:

```bash
# Базовые URL Wildberries
WB_BASE_URL=https://www.wildberries.ru
WB_API_SEARCH_URL=https://www.wildberries.ru/__internal/u-search/exactmatch/ru/common/v18/search

# Параметры запросов
WB_REQUEST_TIMEOUT=10
WB_DELAY_BETWEEN_REQUESTS=0.3
WB_MAX_THREADS=30

# Критерии фильтрации
WB_MIN_RATING=4.5
WB_MAX_PRICE=10000.0
WB_TARGET_COUNTRY=Россия

# Поисковый запрос по умолчанию
WB_DEFAULT_SEARCH_QUERY=пальто из натуральной шерсти

# Логирование
WB_LOG_LEVEL=INFO
WB_LOG_FORMAT_JSON=false
WB_LOG_MAX_BYTES=10485760
WB_LOG_BACKUP_COUNT=5
```

Полный список доступных переменных смотрите в [`src/config/app_settings.py`](src/config/app_settings.py).

## Выходные данные

Результаты работы парсера сохраняются в смонтированный том **`./data/output/`** (внутри контейнера путь `/app/data/output/`). После завершения выполнения там появятся два файла:

1. **`full_catalog.xlsx`** – полный каталог всех найденных товаров
2. **`filtered_catalog.xlsx`** – товары, соответствующие критериям:
   - Рейтинг ≥ 4.5
   - Цена ≤ 10 000 ₽
   - Страна производства: Россия

## ⚠️ Ограничения и рекомендации

- **Частые запросы** могут привести к временной блокировке IP – используйте настройку `WB_DELAY_BETWEEN_REQUESTS`
- **Мониторинг логов** – логи хранятся в папке ./data/logs/ (внутри контейнера путь /app/data/logs/)
- **Лимиты запросов** – для больших объёмов данных рекомендуется использовать прокси-серверы (настройка `WB_PROXY_POOL`)
- **Ротация User-Agent** – включена по умолчанию для снижения вероятности блокировки
- **Экспоненциальный backoff** – автоматически активируется при получении ошибки 429 (Too Many Requests)
